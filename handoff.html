一句话交接

这是一个「AI 生成营销活动页」平台的设计侧工程：产出物是平台自身的界面 + 交互 + 状态流程设计，交给研发实现。本期只做运营 + 设计两个角色的工作台。核心模型（7 阶段 · 7 道人审门 · 状态由「阶段 × 是否卡门」推导）已收口并落到流程图和原型；剩两处待拍板（新建活动入口范式、反复申请破例的可见性），见文末。

核心模型

7 个阶段（运营视角）× 7 道人审门。 状态不再是独立枚举，改为「当前阶段 × 是否卡在门」推导；界面显示的是阶段进度条 + 当前阻塞的门（卡在谁 · SLA · 催办）。各阶段状态标签直接取流程图，例：风格生成中 → 待设计确认① → 页面生成中 → 待设计确认② → …… → 上线中 → 待上线审批 → 已上线 → 已上线·优化中 → 待优化确认 → 已退场；旁路：生成失败 / 已取消。

  • 一个阶段 = 一个交付物 + 一个主责职能 + 一道终局门（拆分判据）。
  • 研发「方案设计 8/8」在运营视角拆成视觉设计（风格定稿→确认①→页面全量生成→确认②）+ 技术方案（点位审核→三方方案→方案定稿→方案人审）。
  • 每道「人审」门内部是多职能并行会签（前端/后端/策略/QA/业务 + 设计），画成一个节点。
  • 需求人审已取消（玩法枚举+schema 校验是确定性的，运营自己确认）；合规前移为生成时硬约束（B 面禁用词库 + 命中转人工）。
  • 设计侧 3 个卡口：确认①核心风格 / 确认②全部页面生成后 / 一次带真实跳转的验收。

玩法与生成链路（确定性优先）

  • 一期玩法是有限枚举（十几种以内），不是开放长尾。需求理解 = 分类路由 + 参数抽取，不是开放式多轮意图理解。
  • LLM 只做「自然语言 → 枚举玩法 + 预填参数」，缺失必填项由 schema 校验补齐；超出枚举明确告知「暂不支持」并回流到设计/研发工作台作为玩法库扩展输入。
  • 骨架/wireframe = 确定性渲染（玩法→模板），秒级零成本、无失败分支。
  • 一期真正的 AI 不确定性只在两处：意图→玩法路由、风格→视觉生成。风格候选用「玩法×风格」预置缩略图，不必实时生图。

已拍板的关键决策（不要推翻）

  • 每个角色要有自己的工作台视角，不能把非运营角色做成「通知 + 点通过」的轻量队列。角色工作流拆两面：(A) 流水线任务面（队列驱动）、(B) 资产/规则治理面（模板库、UI 规范、卡口、发奖概率/反作弊等——AI 生成质量的上游）。
  • 但视角不做「页内切换」：设计/研发/QA 各有顶级工作台；运营的列表页就是纯运营单一视角，一张卡一套操作。不要给某个角色页面塞别的角色视角。
  • 设计审核门：运营提交 → 设计在自己工作台打开活动页全貌 → 可选接棒与 AI 对话改页（改是捷径不是义务）+ 规范细则逐条勾选 → 结论只有通过 / 不通过（含修改意见）。审核工时不在界面展示，只后台留痕。
  • 规范细则清单只留人判项（品牌调性、视觉层级是否引到主 CTA、破例准不准）；机器可判的（对比度/字号栅格/安全区/动效时长/图标来源）下沉为生成时预检，只展示结论。设计侧清单因此从 7 条缩到 3 条。
  • 驳回按门分级退回，不统一回草稿：只作废本门及下游，上游结论保留。产物人审驳回分两档——还原度问题退回实现（默认）；设计要改退回页面全量生成、连带作废方案+实现（须显式选、先告知代价）。上线审批驳回是例外，只退「待上线」、内容结论保留。
  • 上线后原地优化（优化→优化人审），废除旧的「已上线内容锁定、改动即复制新活动」。已上线态保留编辑入口。
  • 版本谱系必须显式：主版本号归运营（送审单位），门内审阅人改动进修订号（v1→v1.1）；界面要能看到「结论绑定哪个版本、diff 基线、下一道门差量基准」；驳回时门内修订随之作废，写进驳回弹层代价行。
  • 策略是独立职能（有方案/实现节点、门席位、审核人名册、B 面资产）。
  • 每个职能关联两个审核人：质量审核人（做得对不对，质量会签）+ 上线审核人（能不能上、能否回滚，上线审批）。名册在各自工作台维护默认值，新建活动带出、可按活动覆盖，同一人兼任需显式勾选。
  • 审核超时只靠催办，不做自动升级/备份审阅人（原型里相关机制已删）。超时 SLA 变红，运营可催办/撤回。

原型交互约定（已落到原型 HTML，别自作主张改）

  • 二次确认只给「不可逆 / 有已花成本 / 影响别人」的动作。正向主流程（确认玩法参数、确认风格）不拦，只给 toast 说明开跑了、要多久。危险档（红）留给作废下游产出、影响线上用户的操作。
  • 弹窗代价行只写时间与影响面，不写金额（全文 ¥ 金额、成本 KPI、预算字段已清空）。例：「已消耗约 50min 不可退 · 重跑还需约 107min」。模型选择只讲质量与时长，不讲成本倍数。
  • 反馈 = 底部居中 toast，2.6s，从下往上滑。已否决右上角与锚定按钮两种方案。它会遮中列底部进度条，暂时接受；要解只让进度条避让，不许移 toast。
  • 三列语义固定：左=对话与信息（时间线/审阅对象），中=预览，右=动作（催办/撤回/取消在右栏底部固定区）。
  • 界面出现人名必须带职能：小圆职能标记 + 姓名（如 设林一 / 后李桁 / 运wuxi12），不用文字前缀或括号补角色。
  • 降认知成本，但别靠解释性小字讲设计意图。优先用界面自身（禁用/锁定/占位/进度分段/二次确认）表达规则；讲不通就改设计，不补文案。改动优先轻量，能复用现有元素（.dfrow/.wtnote 等）就不新增页面/弹层。
